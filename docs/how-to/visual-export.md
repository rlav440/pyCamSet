# GUI visual export coverage

Status: implementation traceability for PCUI-15. This is not a claim of journal compliance or scientific validation.

The guide's transferable constraints are applied here: data and chrome have separate ownership; exports must use source data rather than digitised pixels; image and numeric exports state their fidelity/provenance; UI theme is not a data encoding. Generic size presets are templates only. The preset dimensions are 160 mm screen width at 150 dpi, 85 mm single-column template at 300 dpi, and 180 mm double-column template at 300 dpi. No named-journal convention is asserted.

## Export behavior

- Matplotlib cards offer Save PNG (camera icon), Save SVG and Save PDF (in the ▾ menu beside it, with the export size), and Save CSV. Vector formats are for Matplotlib line art; bitmap image artists remain raster-embedded. SVG/PDF use Matplotlib's vector backend and do not claim all artists become vector paths.
- PNG card presets preserve the live figure size after export and compute exact rounded pixel dimensions from the selected width, original aspect ratio, and DPI. The Phase 1 detection montage and Assess Calibration batch now use generic width/DPI presets.
- CSV is disabled on cards without an explicit source adapter, with a tooltip reason. CSV files begin with one JSON metadata comment, then a conventional CSV header and rows. Metadata identifies phase/run/diagnostic, data kind, units, and axes where known.
- A file-dialog cancellation is a no-op. Save handlers validate the basename, catch failures and show a warning rather than claiming success. Export operations do not modify run diagnostics, threshold parameters, camsets, source images, or target print outputs.
- Scale-bar controls remain disabled when a calibrated pixel-to-world transform and units are unavailable; no scale is inferred from image dimensions.
- The standalone target viewer's command-line export flags remain additive to the Create Target window's Save Target View PNG and Export Target Geometry actions. PLY/OBJ are assembled from the actual PyVista meshes; GLTF is offered only through a renderer API that supports it. Geometry export is unavailable for Matplotlib-only targets, and printable SVG/PDF is not repurposed as scene geometry.
- The Phase 3 lockbox CSV records source and edited camera centres and object centre in source target-frame units, while explicitly marking the physical unit unspecified. PLY contains only those point vertices, not the richer camera-wireframe presentation. The native Open3D PNG comes from the live GUI scene render callback; platform-specific visual appearance and native user interaction still require native acceptance.

### Managed 3D views (Phase 3/4 Assess Calibration)

- The GUI's `Save PNG` action uses the PyVista route and offers generic 160 mm/150 dpi, 85 mm/300 dpi, and 180 mm/300 dpi presets. These determine rendered pixel dimensions while preserving the existing 8:3 composition; they do not assert journal compliance or embed a physical-DPI tag. The view is re-rendered offscreen, not digitised from the screen. Open3D's interactive native window has no screenshot path in this GUI; switch to PyVista for PNG capture.
- `Export 3D geometry…` uses the supported PyVista implementation even when Open3D is selected for interactive viewing. GLTF is the preferred reusable scene export; scene coordinates and material colours are exported, but interactive view state, scalar arrays, physical units and text annotations are not retained. This installed PyVista/VTK exporter writes JSON glTF even when given a `.glb` suffix, so GLB is deliberately not offered.
- OBJ exports scene geometry and material colours through its companion MTL, but loses scalar arrays, units, view state and annotations. PLY exports only reconstructed points in target coordinates. This installed VTK PLY writer drops point arrays, so reprojection-error values are preserved in the JSON sidecar in point-row order; PLY is not a camera scene and has no view or annotation. Every 3D export writes a `.metadata.json` sidecar declaring the coordinate frame, unknown units, and known format losses. COLMAP/APDe exports remain camera calibration interchange, not scene geometry.
- Phase 3/4 Assess Calibration exposes PyVista-only controls for a theme-default or white/charcoal background, point display size, isometric/top/front/side camera, axes, and the reprojection-error legend. Theme defaults follow the active Light/Dark/Sepia application theme. Save style and Load saved persist/apply a versioned JSON preference per assessment visual under the user configuration directory; Reset style removes that saved override and restores theme-default inheritance. The filename is a digest of the fixed visual ID, not user input. Malformed, wrong-version, and cross-visual styles are rejected before controls change. These are presentation options: they do not change point coordinates, scalar values/ranges, camera calibration, or run artefacts. The options also apply to the managed PyVista PNG re-render. Open3D has no managed controls for these properties here; the GUI leaves the controls unavailable and states the limitation, while the separate native viewer retains its own interactive camera controls. Native appearance remains unverified beyond the evidence recorded in this guide's platform limitations.

## Remaining coverage gaps for PCUI-17 acceptance

1. Assess Calibration CSVs do not expose stable target-feature keys, global image indices, or cross-run observation IDs: those identifiers are not carried into the plotted diagnostic arrays. Residual distribution rows have residual-array index only; accuracy/precision rows have feature-array index only; camera coverage rows have camera index/name and within-camera observation order only. No physical scale is inferred from sensor pixels.
2. Phase 1 D1.5 is a bespoke navigation canvas. It has a frame PNG with generic width/DPI presets and observed-coordinate CSV; vector export remains intentionally unavailable for image overlays.
3. Matplotlib-only target geometry is explicitly unavailable.
4. The Phase 3 lockbox Open3D Save 3D view PNG action uses the GUI-only Scene.render_to_image API and captures the rendered 3D scene, not editor controls. Assess Calibration's separate Open3D native viewer does not expose managed PNG capture or the PyVista style controls.
5. Owner-assisted native Windows save/cancel/refusal behaviour has been reviewed for the lockbox export path. Linux/macOS native appearance and interaction, and native appearance of the managed 3D style controls, remain unverified; offscreen verification is not a substitute.
